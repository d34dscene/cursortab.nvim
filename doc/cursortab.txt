INTRODUCTION                                                 *cursortab-intro*

cursortab.nvim is ghost-text completion for Neovim backed by any llama.cpp
server. A FIM model completes while you type. An edit model rewrites during
a pause and predicts where the cursor should land. Models, prompt format and
context window are probed on connect. See |cursortab-dual-mode| for how the
two roles share one ghost text surface.

==============================================================================
SETUP                                                        *cursortab-setup*

Requirements: Neovim 0.8+, Go 1.25+ for the build step, and a llama.cpp
server.

Using lazy.nvim: >lua

  {
    "cursortab/cursortab.nvim",
    lazy = false,
    build = "cd server && go build",
    config = function()
      require("cursortab").setup({
        url = "http://localhost:8000",
        model = "auto",
        next_edit = { model = "auto" },
      })
    end,
  }
<

Using packer.nvim: >lua

  use {
    "cursortab/cursortab.nvim",
    run = "cd server && go build",
    config = function()
      require("cursortab").setup({
        url = "http://localhost:8000",
        model = "auto",
        next_edit = { model = "auto" },
      })
    end,
  }
<

That three-line call is the whole required config. See |cursortab-config|
for every option.

==============================================================================
CONFIGURATION                                               *cursortab-config*

The daemon probes the server on connect:

  - The model list comes from GET /v1/models. It feeds model = "auto" and
    the :Cursortab model picker.
  - The prompt format and FIM tokens come from the model family. Mellum
    gets its <fim_prefix> style tokens, Qwen gets repo tokens, and
    POST /tokenize probes the vocabulary for unknown models.
  - The context window comes from GET /props and falls back to 8192.
  - Sampling stays server side. Every request sends cache_prompt = true so
    llama.cpp reuses the cached prefix.

Full configuration with defaults: >lua

  require("cursortab").setup({
    url = "http://localhost:8000",
    model = "auto",
    api_key_env = "",
    next_edit = { model = "auto" },
    max_tokens = nil,
    context_size = nil,
    fim_tokens = nil,
    quality = { logprobs = false, min_confidence = 0 },
    retrieval = { enabled = false, max_chunks = 0 },
    log_level = "info",
    state_dir = nil,

    keymaps = {
      accept = "<Tab>",
      partial_accept = "<S-Tab>",
      trigger = false,
    },

    ui = {
      completions = {
        addition_style = "dimmed",
        fg_opacity = 0.6,
      },
      jump = {
        symbol = "",
        text = " TAB ",
        show_distance = true,
      },
    },

    behavior = {
      idle_completion_delay = 400,
      text_change_debounce = 35,
      max_visible_lines = 12,
      disabled_in = {},
      enabled_modes = { "insert", "normal" },
      cursor_prediction = {
        enabled = true,
        auto_advance = true,
        proximity_threshold = 3,
      },
      ignore_paths = {
        "*.min.js",
        "*.min.css",
        "*.map",
        "*-lock.json",
        "*.lock",
        "*.sum",
        "*.csv",
        "*.tsv",
        "*.parquet",
        "*.zip",
        "*.tar",
        "*.gz",
        "*.pem",
        "*.key",
        ".env",
        ".env.*",
        "*.log",
      },
      ignore_filetypes = { "", "terminal" },
      ignore_gitignored = true,
    },

    debug = { immediate_shutdown = false },
  })
<

SERVER OPTIONS                                       *cursortab-config-server*

  `url`                                                 *cursortab-config-url*
      Base URL of the llama.cpp server. Default: "http://localhost:8000".
      The type model and the edit model share this URL.

  `model`                                             *cursortab-config-model*
      The type model. Default: "auto", which picks the best FIM model from
      the probe in the order mellum, then qwen, then plain. Set an explicit
      model id to pin one.

  `api_key_env`                                 *cursortab-config-api-key-env*
      Name of an environment variable holding the API key. The value is
      read at daemon startup and sent as the request api key. Default: "",
      no key. Restart the daemon with |:Cursortab-restart| after changing
      the environment.

  `next_edit`                                     *cursortab-config-next-edit*
      The edit model. Default: { model = "auto" }, which picks zeta-2.1,
      then zeta-2, then sweep from the probe. Set the table to nil or
      false, or drop the key, to disable dual mode. Idle requests then go
      to the type model.

  `max_tokens`                                   *cursortab-config-max-tokens*
      Generation cap per role. Default: nil, which uses 64 tokens for the
      type role and 256 for the edit role. Override one or both with
      { type = N, edit = N }.

  `context_size`                               *cursortab-config-context-size*
      Context window in tokens. Default: nil, which probes GET /props and
      falls back to 8192. The prompt and the generation budget stay under
      this window.

  `fim_tokens`                                   *cursortab-config-fim-tokens*
      Explicit FIM token table for exotic models. Default: nil, which
      detects the format from the model family and probes POST /tokenize.
      Keys: prefix, suffix, middle, repo_name, file_sep, filename,
      suffix_first. Set it only when detection guesses wrong. Example: >lua

        fim_tokens = {
          prefix = "<|fim_prefix|>",
          suffix = "<|fim_suffix|>",
          middle = "<|fim_middle|>",
          repo_name = "<|repo_name|>",
          file_sep = "<|file_sep|>",
          filename = "<filename>",
          suffix_first = false,
        }
<
  `quality`                                         *cursortab-config-quality*
      `logprobs`     Request per-token log probabilities and record a mean
                     confidence per completion. Default: false.
      `min_confidence`
                     Drop completions whose mean token logprob is below
                     this floor. Mean logprobs are <= 0, so a gating value
                     is negative, for example -1.5. Default: 0, no gate.
                     Manual triggers bypass the gate.

  `retrieval`                                     *cursortab-config-retrieval*
      `enabled`      Include matching workspace declarations in the
                     prompt. The index builds once per workspace in the
                     background, so the first lookup returns nothing.
                     Default: false.
      `max_chunks`   Cap on retrieved chunks per prompt. Default: 0, which
                     uses 8.

  `log_level`                                     *cursortab-config-log-level*
      Log verbosity: "trace", "debug", "info", "warn" or "error".
      Default: "info". The daemon log lives in |cursortab-config-state-dir|.

  `state_dir`                                     *cursortab-config-state-dir*
      Directory for daemon runtime files: cursortab.log, socket and pid.
      Default: nil, which uses vim.fn.stdpath("state") .. "/cursortab".

------------------------------------------------------------------------------
KEYMAP OPTIONS                                      *cursortab-config-keymaps*

keymaps.accept                               *cursortab-config-keymaps-accept*

  Keymap to accept the shown completion. A keymap string such as "<Tab>",
  or false to disable. Default: "<Tab>".

keymaps.partial_accept               *cursortab-config-keymaps-partial-accept*

  Keymap to partially accept the shown completion. Accepts the next word
  for short completions and the next line for multi-line ones. A keymap
  string such as "<S-Tab>", or false to disable. Default: "<S-Tab>".

keymaps.trigger                             *cursortab-config-keymaps-trigger*

  Keymap to request a completion by hand. A keymap string such as
  "<C-Space>", or false to disable. Default: false. For manual-only
  setups disable both automatic triggers: >lua

    behavior = {
      text_change_debounce = -1,
      idle_completion_delay = -1,
    }
    keymaps = {
      trigger = "<C-Space>",
    }
<
  A manual trigger bypasses every suppression gate.

------------------------------------------------------------------------------
UI OPTIONS                                               *cursortab-config-ui*

ui.completions                               *cursortab-config-ui-completions*

  `addition_style`  Rendering style for additions. "dimmed" (default) or
                    "highlight".
  `fg_opacity`      Opacity for completion overlays, 0 invisible to 1
                    fully visible. Default: 0.6.

ui.jump                                             *cursortab-config-ui-jump*

  `symbol`         Symbol shown before the jump indicator. Default: "".
  `text`           Text shown in the jump indicator. Default: " TAB ".
  `show_distance`  Show line distance for off-screen jumps. Default: true.

------------------------------------------------------------------------------
BEHAVIOR OPTIONS                                   *cursortab-config-behavior*

  `idle_completion_delay`
      Milliseconds of no typing before the edit model is consulted. In
      single mode it retriggers the type model instead. Set -1 to disable.
      Default: 400.

  `text_change_debounce`
      Milliseconds after a text change before the type model runs. Set -1
      to disable. Default: 35.

  `max_visible_lines`
      Maximum visible lines per completion. Longer completions stage into
      views. Set 0 to disable. Default: 12.

  `disabled_in`
      Tree-sitter scopes where completions are suppressed, for example
      { "comment", "string" }. Default: {}.

  `enabled_modes`
      Modes where completions are active. Valid values: "insert" and
      "normal". A mode that is not listed shows no completions and cancels
      in-flight requests. Manual triggers still work. Default: >lua
        { "insert", "normal" }
<

behavior.cursor_prediction       *cursortab-config-behavior-cursor-prediction*

  `enabled`
      Show jump indicators after completions. Default: true.

  `auto_advance`
      When a completion has no code changes, jump to its last line.
      Default: true.

  `proximity_threshold`
      Minimum line distance before a jump indicator is shown instead of a
      direct change. Set 0 to disable. Default: 3.

behavior.ignore_paths                 *cursortab-config-behavior-ignore-paths*

  Glob patterns for files that skip completions. Patterns with "/" match
  the path relative to the working directory, others match the filename.
  Default: >lua
    {
      "*.min.js",
      "*.min.css",
      "*.map",
      "*-lock.json",
      "*.lock",
      "*.sum",
      "*.csv",
      "*.tsv",
      "*.parquet",
      "*.zip",
      "*.tar",
      "*.gz",
      "*.pem",
      "*.key",
      ".env",
      ".env.*",
      "*.log",
    }
<

behavior.ignore_filetypes         *cursortab-config-behavior-ignore-filetypes*

  Filetypes that skip completions. Read-only and non-modifiable buffers
  are skipped already. Default: >lua
    { "", "terminal" }
<

behavior.ignore_gitignored       *cursortab-config-behavior-ignore-gitignored*

  Skip files matched by the repository .gitignore. Default: true.

------------------------------------------------------------------------------
DEBUG OPTIONS                                         *cursortab-config-debug*

immediate_shutdown

  Shutdown the daemon immediately when no clients are connected. Useful
  for development. Default: false.

==============================================================================
DUAL MODE                                                *cursortab-dual-mode*

Two roles share one ghost text surface.

While you type, text changes debounce for behavior.text_change_debounce
(35ms) and the type model answers with a FIM completion.

When you stop typing for behavior.idle_completion_delay (400ms), the edit
model is consulted. A real rewrite replaces the ghost text. The answer can
also carry a cursor target, which renders as a jump indicator. Tab jumps
to it.

An empty edit answer means the edit model has nothing to do. Any valid
type ghost already on screen stays. An edit error or timeout is logged at
Info level and never disables the type path.

Every keystroke supersedes in-flight requests and re-triggers the type
model. Tab, S-Tab and Esc act on whatever is displayed, whichever role
produced it.

With model = "auto" the type role prefers mellum, then qwen, then plain
FIM. With next_edit.model = "auto" the edit role prefers zeta-2.1, then
zeta-2, then sweep.

In single mode, without next_edit, an idle request goes to the type model.

COMMANDS                                                  *cursortab-commands*
                                                                  *:Cursortab*
:Cursortab model                                            *:Cursortab-model*
    Probe url with GET /v1/models, open a picker grouped by role, write
    the chosen models into the config and restart the daemon.

:Cursortab toggle                                          *:Cursortab-toggle*
    Enable or disable cursortab.

:Cursortab restart                                        *:Cursortab-restart*
    Stop and restart the daemon process.

:Cursortab status                                          *:Cursortab-status*
    Show daemon, probe and connection status.

:Cursortab log                                                *:Cursortab-log*
    Open the daemon log in a scratch buffer. The log lives at
    state_dir/cursortab.log.

:Cursortab clear_log                                    *:Cursortab-clear_log*
    Clear the daemon log.

HEALTH                                                      *cursortab-health*

:checkhealth cursortab reports:

  - Probe results for the configured url: models, context window and FIM
    tokens.
  - Configured models with their detected dialects.
  - Connection and reconnect state.

Suppression reasons are logged at Info level in the daemon log at
state_dir/cursortab.log. Open it with |:Cursortab-log|.

  no-edits          an idle or edit request found nothing to rewrite
  disabled-scope    cursor is in a treesitter scope from disabled_in
  single-deletion   the change would only delete text
  low-confidence    mean logprob below quality.min_confidence
  rejection-cache   a similar completion was rejected recently
  stale             a newer keystroke superseded the request
  mode              the current mode is not in behavior.enabled_modes

A manual trigger bypasses every gate.

HIGHLIGHT GROUPS                                         *cursortab-highlight*

All highlight groups are defined with `default = true`, so they can be
overridden by your colorscheme or by calling `nvim_set_hl` before or after
`setup()`.

CursorTabDeletion                                       *hl-CursorTabDeletion*
    Background highlight for deleted text.
    Default: `ctermbg=DarkRed bg=#4f2f2f`

CursorTabAddition                                       *hl-CursorTabAddition*
    Background highlight for added text.
    Default: `ctermbg=DarkGreen bg=#394f2f`

CursorTabModification                               *hl-CursorTabModification*
    Background highlight for modified text shown beside the original.
    Default: `ctermbg=DarkGray bg=#282e38`

CursorTabCompletion                                   *hl-CursorTabCompletion*
    Foreground color for completion ghost text.
    Default: `ctermfg=DarkBlue fg=#80899c`

CursorTabJumpSymbol                                   *hl-CursorTabJumpSymbol*
    Foreground color for the jump indicator symbol.
    Default: `ctermfg=Cyan fg=#373b45`

CursorTabJumpText                                       *hl-CursorTabJumpText*
    Colors for the jump indicator text label.
    Default: `ctermbg=Cyan ctermfg=Black bg=#373b45 fg=#bac1d1`

Example override: >lua
    vim.api.nvim_set_hl(0, "CursorTabAddition", { bg = "#1a3a1a" })
<

LLAMA.CPP SERVING                                            *cursortab-llama*

Serving flags matter more for perceived speed than the model choice:

  - --cache-reuse reuses the KV cache for the unchanged prompt prefix
    across keystrokes. Prompts are prefix-stable, so this is what keeps
    the request after a keystroke fast.
  - Speculative decoding with --model-draft, a small model of the same
    family, typically doubles or triples decode throughput.
  - Keep generations short. The type role defaults to 64 tokens and the
    edit role to 256.

Example: >bash

  llama-server -hf unsloth/Qwen3.5-0.8B-GGUF:Q8_0 --port 8000 --cache-reuse
<

The context window comes from GET /props. Keep the server --ctx-size
accurate so prompts fit.

One router can host both roles and autoload each model on first use. A
router that sleeps models adds cold wake latency to the first request
after idle.
